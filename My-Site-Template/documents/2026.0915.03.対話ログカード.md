Q1:  
1. ディレクトリの走査 & Front Matter の解析
これをするためには…
YAML形式の…
---
type: card
title: 対話ログカード
date: 2026.0915.02
category: Fortune
tags:
- AI
- Technology
- xxx
---
定義づけする必要がありますか？
---
A1:
結論から言うと、**絶対に必須というわけではありませんが、定義しておいた方が処理が圧倒的に安定し、拡張もしやすくなります。**

Front Matter に厳密な定義がない場合と、上記のフォーマットのように定義した場合の違いは以下の通りです。

---

**1. 定義なし（自由形式）の場合**

* **動き:** Python 側で `post.get('title', '無題')` のように、値が存在しなかった場合のデフォルト処理（例外処理）を書けば一応動きます。
* **デメリット:** `date` のフォーマットがバラバラ（例: `2026/09/15` と `2026.0915` など）になるとソート順が崩れたり、タグが文字列（`"AI, Tech"`）とリスト（`["AI", "Tech"]`）で混在すると Python 側でパースエラーの原因になります。

**2. 提示いただいたフォーマットで定義する場合（推奨）**

* **メリット:**
* `type: card` で「Topページのカードにするのか」「詳細記事のみにするのか」などの**フィルタリング**が容易になります。
* `tags` を YAML のリスト形式（`- AI`）で揃えておくことで、HTML 生成時に Python 側の処理（タグごとの絞り込みボタンの作成など）が非常にシンプルになります。
* 日付表記を統一することで、新着順などの**自動並び替えが確実に動きます**。



---

**実践的なアドバイス**

完全に固定しなくても動きますが、最低限 **`title` / `date` / `category`（または `type`）** の3つだけでもテンプレート用の規約（標準フォーマット）として決めておくのがおすすめです。

Python 側のコード内でも、以下のように「キーが存在しない場合のフォールバック（代用値）」を入れておくと、少し記述が抜けた Markdown ファイルがあってもエラーにならず安全です。

```python
# 例: メタデータを取得する際の安全な書き方
title = post.get('title', 'タイトルなし')
date = post.get('date', '1970.01.01')
tags = post.get('tags', []) # タグがなければ空配列

```
