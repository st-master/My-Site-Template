A1:  
「フォルダーによるカプセル化」と「タグによる仮想的なショートカット（横断）」を分離する構造は、非常にシンプルでありながら保守性と拡張性が高く、素晴らしいコンセプトです。

この構想（各フォルダー直下に `build.py` を配置し、カプセル化する運用）に沿った具体的な仕様のイメージです。

---

**1. Front Matter（規約）の解釈**

* **`type`**: `card`, `list`, `video` など、`index.html` 側でレンダリングする際の **HTMLパーツ・コンポーネントの種類** を決定するフラグ。
* **`category`**: 物理的なファイルパス（`./Fortune` など）。カプセル化された実体フォルダーを指し、ディレクトリ構造と1対1で対応。
* **`tags`**: 物理的な階層を無視して、テーマ（`AI` など）ごとにコンテンツを串刺し・検索できるようにする **論理的（バーチャル）ショートカット**。

---

**2. 各フォルダー直下の `build.py` の役割と挙動**

各フォルダーに `build.py` を配置する場合、スクリプトの役割は **「自分のフォルダー内（ `./` ）だけをカプセル化して処理する」** 形になります。

```python
import os
import glob
import subprocess
import frontmatter

# スクリプトがあるフォルダー（自カプセル内）の .md ファイルのみを取得
def build_capsule():
    current_dir = os.path.dirname(os.path.abspath(__file__))
    md_files = glob.glob(os.path.join(current_dir, "*.md"))
    
    cards_data = []
    for filepath in md_files:
        post = frontmatter.load(filepath)
        meta = post.metadata
        
        # 物理パスや相対URLの補完
        meta['path'] = filepath
        cards_data.append(meta)
    
    # 自フォルダー内の index.html や ログ.html を更新
    update_local_html(cards_data)

def run_git_sync():
    # 自フォルダーの変更を Git に反映
    subprocess.run(["git", "add", "."], check=True)
    subprocess.run(["git", "commit", "-m", "auto: Update capsule cards"], check=True)
    subprocess.run(["git", "push", "origin", "main"], check=True)

if __name__ == "__main__":
    build_capsule()
    run_git_sync()

```

---

**3. この設計のメリット**

* **フォルダーごと持ち運び可能（カプセル化）**
`Fortune` フォルダー一式（`*.md` + `build.py` + 生成用HTML）をまるごと別の場所へ移動したり、別リポジトリに移植してもそのまま単体で動作します。
* **タグによる仮想集約（全社視点・Topページ視点）**
ルート（最上位）にも全体用の `build.py` を置けば、各カプセル（`./Fortune`, `./Tech` 等）のメタデータだけを統合して「全タグ横断検索付きの `index.html`」を後から集約作成することも簡単にできます。
